Executive orientation

Three facts to hold through the meeting

The issue is not that five authorities exist. Several are appropriate. The systemic absence is a required selection validation and one durable receipt for every call.

5 → 30

Five concurrent selection authorities govern roughly 30 LLM-call surfaces.

No single answer exists today for “which model runs X?”
432 → 50

Jerry synthesis made 432 real provider calls and committed only 50 products in the Aug 8–21 window.

382 paid attempts did not become a committed state product.
4 lanes

Only four partial lanes meter usage. Highest-volume paths have no token or cost receipt.

The total bill—and incident cost—cannot be computed locally.

The thesis: Fix admission, receipts, and validation first. Keep legitimate independent authorities, and record external ones at the boundary rather than proxying their choices.

The incident, correctly scoped

Aug 8–21, Jerry brain-state synthesis. The proximate freshness cron is disabled. The structural gap is that nothing coalesces duplicate admission before a paid call.

217 discards are not “all Gemma”

  • 217 operations discarded source_changed after the paid call.
  • 327 / 452 were manual trigger; the historic 30-minute freshness cron logged 523 runs and 200 poll-timeout errors.
  • During the window, synthesis moved MiniMax-M3 → claude-haiku-4-5 → gemma4:31b.
  • The right repair is admission-time requestKey coalescing, typed triggers, and a single freshness owner.
Two things currently confused

Settings state is not runtime truth

Save-time validation prevents invalid pairs. Runtime receipts prove what executed. Neither can substitute for the other.

Settings: selection must be valid before it runs

  • Closed role binding
    No bare model string; resolve alias once at the door to an exact provider + model.
  • Declared floor, loudly visible
    Missing bindings resolve to a named floor, never an invisible default catch-all.
  • Pair validation
    Reject provider/model mismatches at save/config time—before OCR or chat call time.
  • Explicit egress grant
    Identity-bearing prompts leave the machine only through a per-surface policy grant.

Runtime: one additive receipt ledger

  • Every provider call
    Surface, role, trigger, caller, requestKey, exact pair, outcome, duration, usage, and cost when available.
  • Wasted-call counter
    Separate attempts, commits, discards, retries, and unknown usage; never invent a cost from missing data.
  • Boundary receipts
    External systems report supplied model/usage; unknown remains unknown, visibly.
  • Read-only Settings view
    Expose effective binding, live receipt evidence, and any divergence without altering runtime.

Target architecture

One contract, deliberate authorities, evidence at every edge

Control only the selections Home23 owns. Make independent systems legible at their boundary.

Selection contract

  • models registry closed roles, aliases, declared floors, provider capability and egress class
  • resolver pure, shadowable, auditable; accepts a role, never a bare model
  • admission same surface + requestKey returns active operation; retry reuses key
  • enforcement roll out by class: cognition, brain ops, chat/workers, media

Evidence and policy contract

  • unified call ledger one durable receipt per call across owned paths
  • boundary ledger external authority, declared egress, supplied outcome/usage, unknown visibly retained
  • privacy policy per-surface identity egress grant; ollama-cloud is egress, not local
  • meter before migrate no cost-motivated model migration without enough receipts to measure it

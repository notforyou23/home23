# Helper and project continuity

Home23 helpers are persistent house agents which run on demand. They share the house tool registry and installed skills. A helper keeps its Bot ID, conversation history, personal workspace, memory objects, relationships, agency journal, coding jobs and schedules across turns and process restarts. It does not acquire a permanent engine or inherit another resident's personal identity. Provider configuration and house service connections come from the installation; individual model selections continue through the existing conversation selection contract.

## Personal and shared context

A helper's direct conversation opens its personal workspace. A group channel opens a shared project workspace under the house projects directory, keyed by the immutable channel ID. Changing a title does not move or replace memory. Each participant remains itself and gets the current project title, purpose, instructions and notes at turn entry. Personal identity maintenance, memory promotion and returned-artifact storage retain their original roots when ordinary file work enters the project directory.

AGENTS.md, MEMORY.md and LEARNINGS.md are initialized without overwriting existing content. The app's Instructions and memory editor and channel_manage project_read/project_write use the same documents and content revisions. Writes reject stale revisions and keep preimages and authorship receipts. The editor preserves unsaved drafts after conflicts and does not advance another document's revision until that document has been reviewed/saved. Ordinary agent file tools remain available; these full-access tools can also edit workspace files directly, outside the revision journal.

Only a bounded excerpt of large documents enters the prompt, with an explicit instruction to read omitted content. Canonical channel history remains the event record and is available through paginated channel_manage history. Notes are authored working knowledge; they are not evidence that a task completed. Existing Seed biography composition remains authoritative for any actual lived record. Creating these files does not fabricate Seed history or a new always-running Seed life.

## Connected capabilities

The helper runtime uses the full registry and connects the house browser/search/media settings, shared skills root, native ACP coding bridge, tracked subagents, worker connector, local Work registry and scheduler. Coding jobs and schedules are owned under the helper's durable Bot directory. Startup restores these lightweight services without starting a permanent model engine. Release rebind preflight includes helper coding jobs, so a host restart cannot silently kill an overlooked coding child.

Personal automatic recall searches the helper's retained files with source paths; it does not call Jerry's personal context search. Engine-backed brain operations remain house services and require a real configured target engine. Helpers have their own existing AgencyKernel journal and retain the same memory-object/relationship machinery used by AgentLoop. Engine-specific operations do not create an engine for a helper, and shared service credentials do not establish a helper-owned engine identity.

Current authenticated Jerry, Forrest and helpers share channel and helper management authority. Current membership, canonical Work leases, cancellation and owner-direction checks still establish who is acting and which assignment is current. Core constructs processless credentials internally. A helper cannot borrow a resident's identity. Joined bot invocation rejects a return to an ancestor which is already waiting for the caller, avoiding a circular assignment deadlock.

Scheduled agent turns enter canonical Work under the scheduling helper's identity and resume the persisted admission. Scheduled shell commands execute directly, and query jobs use the brain-query runner. Their results are persisted before optional channel reporting. An interrupted command without a terminal receipt is reported as uncertain; recovery does not blindly execute it again. Silent command/query jobs stay silent. A manual joined agent job stays under its current Work rather than waiting on another turn of the same helper. Existing resident schedules and delivery settings are not migrated or rewritten.

## Verification and activation

Exercise actual helper tool advertisement and private conversation recovery, current helper lease authority, shared project read/write across store recreation, competing edits, personal/project separation, deterministic command execution, scheduler recreation and silent delivery. Compile the phone editor against the real client. Managed package checks must use the deployed baseline and include the changed service paths. Live process readback and a phone install remain separate operations; a source test or unsigned compile is not live acceptance.

# Conversation context scheduling

Home23's individual is durable. A provider turn receives the individual's identity, carried context and tools; automatic similarity cues supplement that foundation. Making a conversation responsive must not weaken explicit recall, substitute a cheaper cortex, or invent memory absence when a lookup has not finished.

Core marks fresh direct and group conversations with `contextPurpose: conversation` through the signed resident transport. Scheduled assignments, resident initiatives, planned invocations and recovery use `work`. Older canonical callers without this field retain the blocking policy. Legacy foreground chat uses its existing classification. This field controls preparation scheduling only: it does not grant owner identity, speaking admission, file access or execution authority. The durable turn start records it for diagnosis.

A conversation starts one requester-bound automatic lookup and allows 150 ms for already-ready results. Identity, meaning-gated Seed expression, local triggers, relationship continuity, current Work and quoted historical data remain on their existing paths. A pending lookup is disclosed as pending, never as brain failure or memory absence. The model must use explicit brain/relationship tools when its answer depends on facts beyond the context it actually has.

If the automatic request settles later, its bounded, quoted supplement can enter only at the next provider request boundary. It cannot rewrite a request in flight or produce a separate reply. The lookup has an eight-second lifetime, belongs to one turn, and is aborted and discarded when that turn ends. There is no cross-turn cue cache. Late cues retain their automatic-enrichment status and cannot establish an isolated retrieval proof, complete coverage or current truth.

Work retains the existing blocking search and failure evidence. Retrieval evaluations still bypass automatic search and relationship enrichment. Provider, model, reasoning effort, tool grants, memory write receipts and canonical contact authority are unaffected. Warranted memory housekeeping should follow useful answer text when it is not a prerequisite to the requested result; explicit remember/correction requests still require verified writes before success is claimed.

Canonical backfill is included in context-pressure measurement before compaction. The bounded late supplement has reserved space, so deferred recall cannot bypass the provider window. Preparation and supplement-consumption events record timing, size and exact turn identity in the private event ledger.

The tests use actual Core/adapter/UDS and AgentLoop paths with hermetic providers. They cover native purpose propagation, scheduled/recovery isolation, cancellation, deliberate `brain_search`, all configured provider branches, unchanged model selection, prompt budgets and Seed/relationship contracts. They prove orchestration behavior, not live model quality or phone-to-first-text latency. Owner conversation and recall acceptance remains necessary after an authorized activation; expensive model reasoning and the existing full identity/tool payload are still material contributors to latency.

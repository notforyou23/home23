Home23

Product journey preview

A local outline of the Mac-hosted owner path: install Host, create your own home, talk and import documents, open the dashboard, check for updates, and back up or move. This file is documentation for review—not a live product site.

Public downloads are not available yet. There is no published download URL, store listing, or consumer release package to fetch from this page. Do not treat this preview as proof that signing, notarization, TestFlight, or an existing owner’s home is ready for distribution.

Journeys

  1. Install a Mac-hosted home
  2. Create the home and connect your provider
  3. Talk and import documents
  4. Open the dashboard
  5. Check for updates
  6. Back up and move

1. Install a Mac-hosted home

The consumer path starts on a Mac with Home23 Host—the companion that runs and keeps your home. The Mac conversation client is a separate app with its own responsibilities; installing a client does not create another home. Closing a conversation app does not stop the home; availability still depends on Host being running, awake, and reachable.

Intended delivery is a signed, notarized Host download from a public website. That website and download are not selected or published here. Source/operator setup (Git, npm, Terminal) remains a separate developer path and is not the ordinary owner journey described on this page.

2. Create the home and connect your provider

Creating a home is a shared birth operation: your own owner context, residents, purpose, credentials, and Seed lineage. It does not copy another person’s resident or lived memory. After birth, you connect a model provider you control (API key or other supported setup) so the home can talk with your account—not a shared developer fixture.

  • Choose or confirm the resident and home purpose during first-run.
  • Connect your own provider; understand readiness and costs before relying on it.
  • If you already have a home, connect a client or dashboard to that home—do not run birth again.

Hosted homes for people without a Mac are later work, not an available setup button on this preview.

3. Talk and import documents

Once the home is running and a provider is connected, you converse with your resident and bring in documents and context so memory and retrieval belong to that home. Apps and the private dashboard access the same home and residents; feature parity between them should be checked, not assumed.

  • Talk through the Mac client or the home’s private dashboard when those surfaces are available for your install.
  • Import starter folders or documents as part of first-run or later ingestion—not as a copy of someone else’s private library.
  • Embeddings and retrieval readiness are part of setup; an interrupted or degraded path should be explained honestly.

4. Open the dashboard

Each home serves a private web dashboard in a browser. The intended Host action is Open Dashboard, using that home’s actual address. Open Home23 remains the native client action. The dashboard is a full way to use the home; it is not replaced by a public marketing site.

Current packaged services often bind to loopback. A browser on another machine cannot use a Mac’s localhost until a secure home-specific address and access flow exist. Cross-device and Windows browser access are delivery work—not advertised as ready from this page.

5. Check for updates

Host is meant to offer Check for Updates: show the installed version, any available version, release notes, and compatibility. Checking alone must not stop a home, migrate data, or download a runtime. An unavailable or unconfigured feed must not be reported as “up to date.”

Download and Install (when delivered) verifies and stages a release while the current home keeps working, with a chance to defer before a disruptive step and clear recovery if something interrupts.

Network installation, publisher trust, and a native update feed for consumer homes remain unfinished. A local engineering preview of package comparison is not the same as a shipped Check for Updates button.

6. Back up and move

Back Up Home and Move Home preserve the existing home rather than create a new resident. Restore verifies the archive and required runtime before writers start again. Missing external folders, services, or credentials should appear as reconnection work—not as silent omissions.

Backup, move, and existing-owner adoption are planned delivery work. This preview does not claim they are finished or that any particular home has been migrated.

Home23

Release preview

Local outline of the Mac-hosted owner path: install Host, create your own home, talk and import documents, open the dashboard, check for updates, recover, and back up or move. This file is documentation for review—not a live product site and not a download page.

Public downloads are unavailable. There is no published download URL, store listing, consumer release package, or public update feed to fetch from this page. The September 22 06:44 stub package (fixture candidate with stub Node) is not a release. Do not treat this preview as proof that Developer ID signing, notarization, TestFlight, or an existing owner’s home is ready for distribution.

Journeys

1. Install a Mac-hosted home

The consumer path starts on a Mac with Home23 Host—the companion that runs and keeps your home. The Mac conversation client is a separate app; installing a client does not create another home. Closing a conversation app does not stop the home; availability still depends on Host being running, awake, and reachable.

Engineering assembly (not performed from this page) builds a product payload with node scripts/product/package.mjs, then a Host app with home23-apple/scripts/build-home23-host.mjs. See SIGNING.md for the owner approval sequence before any of that becomes a public download.

Intended delivery is a signed, notarized Host download from a public website. That website and download are not selected or published here. Source/operator setup (Git, npm, Terminal) remains a separate developer path.

2. Create the home and connect your provider

Creating a home is a shared birth operation: your own owner context, residents, purpose, credentials, and Seed lineage. It does not copy another person’s resident or lived memory. After birth, connect a model provider you control so the home talks with your account—not a shared developer fixture.

  • Choose or confirm the resident and home purpose during first-run.
  • Connect your own provider; understand readiness and costs before relying on it.
  • If you already have a home, connect a client or dashboard to that home—do not run birth again.

Hosted homes for people without a Mac are later work, not an available setup button on this preview.

3. Talk and import documents

Once the home is running and a provider is connected, converse with your resident and bring in documents so memory belongs to that home. Apps and the private dashboard access the same home; feature parity should be checked, not assumed.

  • Talk through the Mac client or the home’s private dashboard when those surfaces are available for your install.
  • Import starter folders or documents as part of first-run or later ingestion—not as a copy of someone else’s private library.
  • Embeddings and retrieval readiness are part of setup; an interrupted or degraded path should be explained honestly.

4. Open the dashboard

Each home serves a private web dashboard in a browser. The intended Host action is Open Dashboard, using that home’s actual address. Open Home23 remains the native client action. The dashboard is a full way to use the home; it is not replaced by a public marketing site.

Current packaged services often bind to loopback. A browser on another machine cannot use a Mac’s localhost until a secure home-specific address and access flow exist. Cross-device and Windows browser access are delivery work—not advertised as ready from this page.

5. Check for updates

Host is meant to offer Check for Updates: show the installed version, any available version, release notes, and compatibility. Checking alone must not stop a home, migrate data, or download a runtime. An unavailable or unconfigured feed must not be reported as “up to date.”

Development Check can pass a local --trust-key only when the dispatched runtime’s app/scripts/product/host-command-contract.json lists check-update in trustKeyActions (Apple 243147d, backend 8903df6c). A missing or older contract omits the flag. That verifies a development Ed25519 signature over the release packageId; it is not public publisher trust. Production trust claims and bad signatures are refused. canInstall stays false on Check.

Download and Install (when delivered) verifies and stages a release while the current home keeps working, with a chance to defer before a disruptive step and clear recovery if something interrupts. Download and install-staged still require a development trust key on controllers that accept those actions.

There is no public update feed. The 06:44 stub package is fixture-only and must not be installed as a release. A runnable install may be in progress elsewhere; do not treat earlier ~33–35 minute preview timings as the measured wall time for that trial. Record that trial’s own elapsed time when it finishes.

6. Recovery and adoption

Interrupted update recovery resumes from durable journal evidence for that home. A stopped home must remain stopped; desired-running choice is preserved across a successful cutover. Recovery after a failed or interrupted update is not the same as adopting a managed or source installation into a product home.

Managed and source adoption stay unavailable until a held supervisor fence exists that keeps every resident’s writers quiet for the copy window. A completed adoption journal alone is not success (supervisor_fence_unavailable). Product writer lists and release maintenance locks are not that fence. Multi-resident managed homes are unsupported until each resident’s process set and Seed identity are preserved under the fence.

7. Back up and move

Back Up Home and Move Home preserve the existing home rather than create a new resident. Backup streams an encrypted archive only when owned writers are quiet and the host lifecycle lock is held. Inspect/restore authenticates the archive before writers start. Move restores into an empty destination, rebinds that copy’s home path, and fences the source so Start there refuses rather than running two lives of one individual.

Missing external folders, services, or credentials should appear as reconnection work—not as silent omissions. Native Host UI for these operations is delivery work; operator host commands are not a substitute for a finished owner journey.

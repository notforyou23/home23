# Hosted PGS operation contract

Read only when PGS is supported by the configured service and permitted for this instance. Tool registration alone does not establish hosting or authority. A missing capability or `pgs_not_hosted` response is final for that route; do not bypass it through a hardcoded URL. Local brain search does not require PGS.

Use `brain_pgs_partitions` to obtain canonical partition IDs before targeted work; never invent IDs.

  Enable PGS for coverage: set enablePGS=true, choose pgsMode and pgsLevel, and pass exact pgsSweep/pgsSynth provider-model pairs. Agent PGS launches detached immediately: report the exact operation ID, remain available, and check it later with nonblocking status/result calls. PGS levels are cumulative coverage budgets: skim (10%), sample (25%), deep (50%), full (100%). Fresh starts a new sweep. Continue resumes an exact prior PGS operation and requires continueFromOperationId. Targeted limits work to unique canonical c-/h- targetPartitionIds and may also continue an existing targeted operation.
  When brain_status reports a retryable provider_stalled PGS with durable successful/reused work and pending work, resume only when the exact original inputs are available: failed brain_status output does not expose them all, so never infer missing lineage values. Manually resume with brain_query using enablePGS=true, the exact same query, brain target, and pgsLevel, and the exact same pgsSweep and pgsSynth pairs. For a level/fresh lineage use pgsMode='continue' with continueFromOperationId set to the stalled operation ID. For a targeted lineage use pgsMode='targeted' with that continueFromOperationId and the exact cumulative prior targetPartitionIds. Preserve and report the new operation ID; do not start fresh or claim brain loss.
  In targeted mode, the level is applied across the cumulative target-partition union; use full when every work unit in the named partitions must run. A targeted continuation must include all earlier target IDs plus any new IDs, so completed units are reused and the scope never shrinks.
  PGS scope matters: an empty scoped result is not proof of full-brain absence. State the searched level and partitions before making an absence claim.

An explicitly requested PGS reattachment can wait up to six hours. Keep the exact returned operation ID. Outside a canonical Working Thread, Chat Stop detaches durable work without cancelling it; use brain_status action:"cancel" for the exact operation ID to cancel. Inside a joined Working Thread, Stop requests cancellation of the joined operation and waits for its terminal confirmation. A detached observer is never proof that the underlying operation stopped.
